# 岗位 Agent 对照评测

使用同一份脱敏简历与 10 条带人工标签的虚构岗位。评测申请人设为本科、可在澳大利亚远程工作。样本数据和每次查询可见的候选集合见 [agent_jobs.json](../examples/agent_jobs.json)。

前五命中统计人工标为「值得投递」的岗位。硬冲突包含 3 个明确只招博士的岗位及 1 个美国限定岗位。「博士优先」标为可考虑。引用可定位表示 JD 引用是实际取得的原文子串，简历引用与行号指向本次简历。一次“精读”表示核对一份候选的已取得 JD，来源随搜索提供全文，因此不一定对应独立网络请求。

| 路径 | 前五值得投递 | 前五硬冲突 | 可定位引用 | 搜索 / 精读 / 简历检索 / 模型调用 |
| --- | ---: | ---: | ---: | --- |
| 旧规则，首轮即排名 | 1 / 5 | 3 | 25 / 25 | 1 / 5 / 0 / 0 |
| 旧规则，预先拿到完整 10 条语料 | 4 / 5 | 1 | 23 / 23 | 0 / 10 / 0 / 0 |
| Agent，首轮偏离后补搜 | 5 / 5 | 0 | 23 / 23 | 2 / 9 / 1 / 0 |
| Agent，首轮已足够 | 5 / 5 | 0 | 23 / 23 | 1 / 5 / 1 / 0 |

旧规则首轮把博士岗的技术关键词当作强信号。给旧规则完整语料后，前五仍有一份明确博士要求的 JD。Agent 演示读取实际要求后用 FastAPI 方向补搜，区分了博士必需与优先。补搜与去重之后实际精读 9 份。另有测试覆盖搜索失败后停止，以及等待地区回答并以同一 run 恢复。

运行 `python -m scripts.evaluate_agent` 可查看岗位 ID 与计数。上述指标仅反映这组构造样本和可控决策，不代表模型在开放岗位上的准确率。真实模型工具调度使用可控 Provider 替身做了接口回归；真实 OpenAI 效果需要使用服务端密钥另行验证。
